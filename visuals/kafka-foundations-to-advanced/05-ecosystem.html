🔄 CDC + Outbox: Reliable Events from a Database

👀 Read it top to bottom: each message is sent in turn, and a dot travels from the sender to the receiver. Dashed lines are replies.

Step by step

  1. Order service → Postgres: BEGIN → INSERT order → INSERT outbox(event) → COMMIT
  2. Debezium → Postgres: read WAL (logical replication)
  3. Debezium → Kafka: publish OrderCreated (from outbox row)
  4. 📝 Order service, Kafka: no dual write → no lost or phantom events ✅

Compatibility mode Allowed change Upgrade order
BACKWARD (default) Delete fields, add optional fields Consumers first
FORWARD Add fields, delete optional fields Producers first
FULL Only add or remove optional fields Any order
NONE Anything goes ❌ Pain

Formats: Avro (compact, schema evolution), Protobuf (typed, gRPC-friendly), JSON Schema. Registries include Confluent Schema Registry, Apicurio and Karapace.

🎯 Exactly-Once Semantics (EOS)

👀 Read it top to bottom: each message is sent in turn, and a dot travels from the sender to the receiver. Dashed lines are replies.

Consume → process → produce atomically: output records and consumer offsets commit together, or not at all.

Piece Setting
Producer transactional.id=<stable unique id> (implies idempotence)
Consumer of outputs isolation.level=read_committed
Kafka Streams Just set processing.guarantee=exactly_once_v2 ✨

⚠️ EOS covers Kafka → Kafka. Side effects outside Kafka (HTTP calls, DB writes) still need idempotency or the outbox pattern.

Step by step

  1. App (transactional.id=billing-1) → Transaction coordinator: initTransactions (fences zombie instances)
  2. App (transactional.id=billing-1) → orders (input): poll records
  3. App (transactional.id=billing-1) → Transaction coordinator: beginTransaction
  4. App (transactional.id=billing-1) → invoices (output): send invoice records
  5. App (transactional.id=billing-1) → Transaction coordinator: sendOffsetsToTransaction(input offsets)
  6. App (transactional.id=billing-1) → Transaction coordinator: commitTransaction ✅
  7. 📝 invoices (output): consumers with isolation.level=read_committed see the outputs only after the commit
