🏛️ Cluster Architecture (KRaft)

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

  • Since Kafka 4.0, ZooKeeper is gone. Metadata lives in an internal Raft log managed by KRaft controllers.
  • Every partition has one leader and N−1 followers (replicas on other brokers).
  • Clients bootstrap from any broker, fetch metadata, then talk directly to partition leaders.
  • Small clusters can run in combined mode (broker + controller in one process). Production usually uses dedicated controllers.

Step by step

  1. controller 1 👑 active ⇢ broker 1 orders-0 👑 orders-1 replica metadata
  2. controller 1 👑 active ⇢ broker 2 orders-1 👑 orders-2 replica metadata
  3. controller 1 👑 active ⇢ broker 3 orders-2 👑 orders-0 replica metadata
  4. Producer → broker 1 orders-0 👑 orders-1 replica write to leader
  5. Consumer → broker 3 orders-2 👑 orders-0 replica read from leader or nearest replica

🔁 Basic Flow

👀 Read it top to bottom: each message is sent in turn, and a dot travels from the sender to the receiver. Dashed lines are replies.

Step by step

  1. Producer → Leader (broker 1): produce batch → orders-0
  2. Leader (broker 1) → Leader (broker 1): append to log (offset 120..149)
  3. Followers → Leader (broker 1): fetch (replicate)
  4. Leader (broker 1) ⇠ Producer: ack ✅ (acks=all: once ISR has it)
  5. Consumer group → Leader (broker 1): fetch from offset 120
  6. Leader (broker 1) ⇠ Consumer group: records 120..149
  7. Consumer group → Consumer group: process
  8. Consumer group → Leader (broker 1): commit offset 150 (stored in __consumer_offsets)
