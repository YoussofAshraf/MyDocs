🏭 Inside a Producer

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

Step by step

  1. app.send record → Serializer key + value → bytes
  2. Serializer key + value → bytes → Partitioner which partition?
  3. Partitioner which partition? → Record accumulator batches per partition batch.size · linger.ms
  4. Record accumulator batches per partition batch.size · linger.ms → Sender thread compression · in-flight requests
  5. Sender thread compression · in-flight requests → Partition leader produce request
  6. Partition leader → Sender thread compression · in-flight requests ack / error
  7. Sender thread compression · in-flight requests → app.send record callback / future

✅ Acknowledgements (acks)

👀 Read it top to bottom: each message is sent in turn, and a dot travels from the sender to the receiver. Dashed lines are replies.

Combine with min.insync.replicas=2 on the topic (ch. 04) for true durability.

Step by step

  1. Producer → Leader: produce (acks=all)
  2. Leader → Leader: append
  3. Follower 1 → Leader: fetch ✅
  4. Follower 2 → Leader: fetch ✅
  5. Leader ⇠ Producer: ack (all in-sync replicas have it)

🔂 Idempotent Producer (No Duplicates on Retry)

 Without idempotence:                       With enable.idempotence=true (default): send m1 → leader writes → ack lost 🌩️       send m1 [PID=7, seq=0] → written, ack lost retry m1 → written AGAIN → duplicate ❌      retry  [PID=7, seq=0] → broker: seen seq 0 → drop ✅

👀 The drawing is revealed line by line. Arrows pulse, and ✅ / ❌ marks pop in to show the verdicts.

  • Each producer gets a Producer ID, and each record a sequence number per partition.
  • The broker drops duplicates and keeps order even with retries and multiple in-flight requests (≤ 5).
  • Gives exactly-once writes per partition per producer session. Cross-partition atomicity needs transactions (ch. 05).

Setting Effect Typical value
batch.size Max bytes per partition batch 64 KB – 1 MB for throughput
linger.ms Wait to fill batches (default 5 ms in newer clients) 5–50 ms
compression.type lz4 / zstd / snappy / gzip lz4 or zstd ⭐
buffer.memory Total producer buffer 32 MB+
max.in.flight.requests.per.connection Pipelining ≤ 5 (with idempotence)
delivery.timeout.ms Upper bound for send + retries 120 s default
