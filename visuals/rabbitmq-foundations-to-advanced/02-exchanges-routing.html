🎯 Direct Exchange

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

The message with key error reaches errors-queue and alerting-queue (both bound with error). The info queue gets nothing.

Step by step

  1. Producer → direct: logs key: error
  2. direct: logs → errors-queue binding key: error
  3. direct: logs → info-queue binding key: info
  4. direct: logs → alerting-queue binding key: error

📻 Fanout Exchange

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

Each queue gets its own copy. This is pub/sub: add a subscriber by binding a new queue.

Step by step

  1. Producer → fanout: user.updated any key, ignored
  2. fanout: user.updated → search-indexer
  3. fanout: user.updated → cache-invalidator
  4. fanout: user.updated → audit-log

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

Use them to build routing hierarchies without changing producers.

Step by step

  1. Producer → topic: all-events
  2. topic: all-events → fanout: orders order.#
  3. topic: all-events → topic: eu-events #.eu
  4. fanout: orders → billing
  5. fanout: orders → analytics
  6. topic: eu-events → gdpr-audit

🧭 Which Exchange Should I Use?

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

Step by step

  1. Every subscriber gets every message? → fanout Yes
  2. Every subscriber gets every message? → Route by exact key? No
  3. Route by exact key? → direct Yes
  4. Route by exact key? → Hierarchical keys + wildcards? No
  5. Hierarchical keys + wildcards? → topic ⭐ most flexible Yes
  6. Hierarchical keys + wildcards? → headers No
