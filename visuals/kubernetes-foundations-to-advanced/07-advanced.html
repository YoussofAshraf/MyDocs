🧬 Extending Kubernetes: CRDs + Operators

Kubernetes is a platform for building platforms. You can teach it new object types.

Step by step

  1. CustomResourceDefinition defines kind: PostgresCluster → API Server
  2. 👤 kubectl apply PostgresCluster 'orders' replicas: 3, version: 16 → API Server
  3. 🤖 Operator custom controller → API Server watch
  4. 🤖 Operator custom controller → StatefulSet reconcile
  5. 🤖 Operator custom controller → Services
  6. 🤖 Operator custom controller → Secrets
  7. 🤖 Operator custom controller → Backups CronJob
  8. 🤖 Operator custom controller → StatefulSet failover, upgrades

📦 Packaging: Helm vs Kustomize

        HELM  (templating + releases)              KUSTOMIZE  (overlays, no templates)  ┌───────────────────────────┐              ┌──────────────────────────┐  │ chart/                    │              │ base/                    │  │  ├── Chart.yaml           │              │  ├── deployment.yaml     │  │  ├── values.yaml          │              │  └── kustomization.yaml  │  │  └── templates/*.yaml     │              │ overlays/                │  │        {{ .Values.x }}    │              │  ├── dev/  (patch: 1 rep)│  └─────────────┬─────────────┘              │  └── prod/ (patch: 6 rep)│                │ helm install -f prod.yaml  └────────────┬─────────────┘                ▼                                         ▼ kubectl apply -k overlays/prod           Release v3 (rollback-able)                plain YAML

👀 The drawing is revealed line by line. Arrows pulse, and ✅ / ❌ marks pop in to show the verdicts.

Helm Kustomize
Approach Go templates + values Patches over plain YAML
Distribution Charts in OCI registries ✅ Git directories
Best for Third-party apps, configurable packages Your own apps, env overlays

They combine well: Kustomize can render Helm charts, and Argo CD supports both.

🔄 GitOps

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

Git is the source of truth. An in-cluster agent pulls and reconciles.

Push CD (classic) GitOps (pull)
CI holds cluster credentials Credentials stay inside the cluster 🔐
No drift detection Continuous drift correction
Rollback = rerun the pipeline Rollback = git revert

Step by step

  1. 👩‍💻 Dev → App repo PR
  2. App repo → CI: test, build, scan, push image
  3. CI: test, build, scan, push image → Config repo Helm / Kustomize bump image tag PR
  4. Config repo Helm / Kustomize → 🐙 Argo CD / Flux in cluster pull & sync
  5. 🐙 Argo CD / Flux in cluster → ☸️ Cluster
  6. 🐙 Argo CD / Flux in cluster ⇢ ☸️ Cluster drift detected → self-heal

🔭 Observability: The Three Pillars (+1)

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

Pillar Answers K8s sources
Metrics Is something wrong? kube-state-metrics, node-exporter, cAdvisor
Logs What happened? Container stdout → Fluent Bit / Vector
Traces Where is it slow? OpenTelemetry auto-instrumentation
Events What did K8s do? kubectl get events, event exporter

Alert on symptoms (SLOs: latency, errors, saturation) rather than causes.

Step by step

  1. app + OpenTelemetry SDK → Prometheus / Mimir metrics
  2. app + OpenTelemetry SDK → Loki / Elasticsearch logs
  3. app + OpenTelemetry SDK → Tempo / Jaeger traces
  4. app + OpenTelemetry SDK ⇢ Pyroscope profiles
  5. OTel Collector → app + OpenTelemetry SDK
  6. Prometheus / Mimir → 📊 Grafana
  7. Loki / Elasticsearch → 📊 Grafana
  8. Tempo / Jaeger → 📊 Grafana
  9. Prometheus / Mimir → 🚨 Alertmanager → Slack / PagerDuty

🕸️ Service Mesh

Without mesh                          With mesh (sidecar or ambient/eBPF)────────────                          ──────────────────────────────────[A] ───plain HTTP───▶ [B]             [A]─[proxy] ══mTLS══▶ [proxy]─[B] retries, TLS, metrics                       ▲                 ▲ coded in every app                          └─ control plane ─┘                                             (Istio, Linkerd, Cilium)

👀 The drawing is revealed line by line. Arrows pulse, and ✅ / ❌ marks pop in to show the verdicts.

You get: mTLS everywhere, retries and timeouts, traffic splitting, golden metrics, and authorization policies, all without changing app code. ⚠️ The cost is added complexity and latency. Adopt a mesh when you need it.

🌍 Multi-Cluster & Platform Engineering

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

Need Tools
Create and upgrade clusters declaratively Cluster API, managed (EKS, GKE, AKS), Talos
Deploy to many clusters Argo CD ApplicationSets, Flux, Fleet
Cloud infra from K8s Crossplane
Cross-cluster networking Cilium ClusterMesh, Istio multi-primary, Submariner
Multi-tenancy Namespaces + RBAC + quotas, vCluster, Capsule
Cost visibility OpenCost, Kubecost

Step by step

  1. 🧭 Internal Developer Platform Backstage portal, templates → Git
  2. Git → Management cluster Argo CD ApplicationSets, Crossplane, Cluster API
  3. Management cluster Argo CD ApplicationSets, Crossplane, Cluster API → ☸️ prod-eu
  4. Management cluster Argo CD ApplicationSets, Crossplane, Cluster API → ☸️ prod-us
  5. Management cluster Argo CD ApplicationSets, Crossplane, Cluster API → ☸️ staging
  6. Management cluster Argo CD ApplicationSets, Crossplane, Cluster API → ☸️ edge k3s fleet
