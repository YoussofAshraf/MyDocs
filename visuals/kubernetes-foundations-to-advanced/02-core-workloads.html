🧩 The Workload Family Tree

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

💡 You rarely create bare Pods. You create a controller that manages Pods for you.

Step by step

  1. ReplicaSet N identical Pods → Pod smallest unit
  2. Deployment stateless apps + rollouts → ReplicaSet N identical Pods
  3. StatefulSet stable identity + storage → Pod smallest unit
  4. DaemonSet one Pod per node → Pod smallest unit
  5. Job run to completion → Pod smallest unit
  6. CronJob Jobs on a schedule → Job run to completion

A Pod is one or more containers that share a network namespace (same IP, localhost) and volumes.

Pattern Purpose Example
Init container Setup before the app starts DB migrations, wait-for-dependency
Sidecar Runs alongside the app for its whole life Log shipper, proxy (native sidecars use restartPolicy: Always on an init container)
Ambassador / Adapter Proxy or reformat traffic or metrics Local DB proxy, metrics exporter

🫛 Pods

Pod lifecycle

👀 States appear one after another and each transition draws in order. ● is the start and ◉ is the end.

Step by step

  1. ● → Pending created
  2. Pending → Running scheduled + images pulled
  3. Running → Succeeded all containers exit 0
  4. Running → Failed a container exits ≠ 0 (no restart)
  5. Running → Running restart (CrashLoopBackOff if repeated)
  6. Pending → Failed e.g. ImagePullBackOff persists
  7. Succeeded → ◉
  8. Failed → ◉

For databases, queues and clustered systems that need stable identity.

Deployment StatefulSet
Pod names random (web-7d9f-x2k) ordinal (db-0)
Storage shared or none one PVC per Pod (volumeClaimTemplates)
Ordering parallel ordered
Use for APIs, web, workers Postgres, Kafka, Elasticsearch

🧭 Which Workload Should I Use?

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

Step by step

  1. Runs forever? → On a schedule? No
  2. On a schedule? → CronJob Yes
  3. On a schedule? → Job No
  4. Runs forever? → Needed on every node? Yes
  5. Needed on every node? → DaemonSet Yes
  6. Needed on every node? → Needs stable identity or per-Pod storage? No
  7. Needs stable identity or per-Pod storage? → StatefulSet Yes
  8. Needs stable identity or per-Pod storage? → Deployment No
