🌐 The Kubernetes Network Model

👀 The drawing is revealed line by line. Arrows pulse, and ✅ / ❌ marks pop in to show the verdicts.

Three rules that every CNI plugin implements:

  1. Every Pod gets its own IP.
  2. Pods can reach all other Pods without NAT, across nodes.
  3. Agents on a node (such as the kubelet) can reach all Pods on that node.

Pod IPs change whenever Pods are recreated. Services solve that.

Type Reachable from Use
ClusterIP Inside the cluster Service-to-service traffic
NodePort nodeIP:port Dev, bare metal, behind an external LB
LoadBalancer Internet or VPC Exposing one service directly
ExternalName n/a (a DNS CNAME) Aliasing an external host
Headless (clusterIP: None) DNS returns Pod IPs StatefulSets, client-side load balancing

🚪 Ingress: HTTP Routing into the Cluster

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

Step by step

  1. 🌍 Users → Cloud LB
  2. Cloud LB → Ingress Controller NGINX / Traefik / HAProxy
  3. Ingress Controller NGINX / Traefik / HAProxy → svc: frontend shop.com/
  4. Ingress Controller NGINX / Traefik / HAProxy → svc: api shop.com/api
  5. Ingress Controller NGINX / Traefik / HAProxy → svc: admin admin.shop.com
  6. svc: frontend → pods
  7. svc: api → pods
  8. svc: admin → pods
