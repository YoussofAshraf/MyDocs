🔐 Permissions Gotcha

host file owner: uid 1000 (you)container user:  uid 999 (postgres)  →  Permission denied ❌ Fixes:  • run as a matching user:      docker run -u $(id -u):$(id -g) ...  • chown in the Dockerfile:     COPY --chown=app:app . .  • use named volumes (Docker sets them up from the image's ownership)  • SELinux hosts: append :z or :Z to the bind mount

💾 Back Up & Restore a Volume

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

Step by step

  1. volume pgdata → temp alpine container mounted ro
  2. temp alpine container → ./backup/pgdata.tgz tar czf
  3. ./backup/pgdata.tgz → temp container tar xzf
  4. temp container → new volume

🧬 Storage Drivers (Under the Hood)

  merged/   ← what the container sees     ▲  upperdir  (writable layer)        ← copy-on-write target  lowerdir  L3 : L2 : L1 (image)    ← read-only

👀 The drawing is revealed line by line. Arrows pulse, and ✅ / ❌ marks pop in to show the verdicts.

Images and writable layers are combined by a storage driver, usually overlay2 (OverlayFS). Newer installs may use the containerd image store with snapshotters.

Heavy write workloads (databases, logs) should go to volumes, which bypass copy-on-write.

  2. copy-on-write target
  3. read-only
