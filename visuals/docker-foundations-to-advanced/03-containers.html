What happens behind the scenes:

Sequence · 2/4

🏃 Anatomy of docker run

👀 Read it top to bottom: each message is sent in turn, and a dot travels from the sender to the receiver. Dashed lines are replies.

Step by step

  1. docker CLI → dockerd: run myorg/api:1.4.2
  2. dockerd → dockerd: image local?
  3. dockerd → Registry: pull layers
  4. Registry ⇠ dockerd: layers (sha256)
  5. dockerd → dockerd: create writable layer, network, mounts
  6. dockerd → containerd/runc: create + start
  7. containerd/runc → containerd/runc: namespaces + cgroups → exec process
  8. containerd/runc ⇠ docker CLI: container ID ✅

🛑 Graceful Shutdown

docker stop api   │   ├─▶ SIGTERM to PID 1 ──▶ app closes connections, flushes data   │        ⏳ 10s grace period (--stop-timeout / -t)   └─▶ SIGKILL if still running 💀

👀 The drawing is revealed line by line. Arrows pulse, and ✅ / ❌ marks pop in to show the verdicts.

⚠️ PID 1 inside a container doesn't get default signal handlers. If your app ignores SIGTERM, use the exec-form CMD and --init (tini), or handle the signal in code.
