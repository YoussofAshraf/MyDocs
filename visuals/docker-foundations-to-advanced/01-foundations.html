🤔 The Problem Docker Solves

  "It works on my machine" 😩                  With containers 😎  ──────────────────────────                   ─────────────────────────────  Dev laptop:  Node 20, libssl 3               Image = app + runtime + libs  Staging:     Node 18, libssl 1.1    ───▶     Same image runs on laptop,  Prod:        Node 16, missing lib            CI, staging and prod

👀 The drawing is revealed line by line. Arrows pulse, and ✅ / ❌ marks pop in to show the verdicts.

A container is a normal Linux process that is isolated (it gets its own view of files, network and processes) and limited (CPU and memory caps), started from a packaged filesystem called an image.

        Virtual Machines                          Containers ┌──────────┬──────────┬──────────┐    ┌──────────┬──────────┬──────────┐ │  App A   │  App B   │  App C   │    │  App A   │  App B   │  App C   │ │  Libs    │  Libs    │  Libs    │    │  Libs    │  Libs    │  Libs    │ │ Guest OS │ Guest OS │ Guest OS │    ├──────────┴──────────┴──────────┤ ├──────────┴──────────┴──────────┤    │        Container Runtime        │ │           Hypervisor            │    ├─────────────────────────────────┤ ├─────────────────────────────────┤    │   Host OS (one shared kernel)   │ │            Host OS              │    ├─────────────────────────────────┤ ├─────────────────────────────────┤    │         Infrastructure          │ │         Infrastructure          │    └─────────────────────────────────┘ └─────────────────────────────────┘

👀 The drawing is revealed line by line. Arrows pulse, and ✅ / ❌ marks pop in to show the verdicts.

Virtual Machine Container
Isolates Hardware (full guest OS) Processes (shared host kernel)
Boot time Tens of seconds to minutes Milliseconds to seconds
Size GBs MBs
Density Tens per host Hundreds per host
Isolation strength Stronger Weaker (shared kernel), hardened with gVisor or Kata

💡 On macOS and Windows, Docker runs containers inside a small Linux VM, because containers need a Linux kernel.

Flow · 3/6

🏛️ Docker Architecture

👀 Boxes light up as the flow reaches them and each arrow draws in the order the guide defines it. Glowing dots keep running along the arrows to show which way things move.

Component Role
docker CLI Sends your commands to the daemon's API
dockerd Manages images, networks, volumes and builds
BuildKit The modern build engine (parallel, cached, secret-aware)
containerd Industry-standard runtime that manages container lifecycle (Kubernetes uses it too)
runc Low-level OCI runtime that actually creates the container, then exits
shim Keeps the container running if dockerd or containerd restarts
Registry Stores and distributes images

🔐 Access to docker.sock is effectively root on the host. Guard it.

Step by step

  1. runc → Container
  2. runc → Container
  3. dockerd Docker daemon REST API → BuildKit builder
  4. dockerd Docker daemon REST API → containerd container lifecycle
  5. containerd container lifecycle → containerd-shim
  6. containerd-shim → runc
  7. containerd container lifecycle → containerd-shim
  8. containerd-shim → runc
  9. 💻 docker CLI → dockerd Docker daemon REST API unix socket /var/run/docker.sock
  10. docker compose → dockerd Docker daemon REST API
  11. docker buildx → BuildKit builder
  12. dockerd Docker daemon REST API → 📦 Registry Docker Hub · GHCR · ECR push / pull

🧱 Image vs Container

       IMAGE (read-only layers)                CONTAINER = image + thin writable layer  ┌──────────────────────────────┐        ┌──────────────────────────────┐  │                              │        │  ✍️ writable layer (changes)  │ ← lost on rm  │  L4  COPY app/ .             │        ├──────────────────────────────┤  │  L3  RUN npm ci              │  run   │  L4  COPY app/ .             │  │  L2  RUN apt-get install ... │ ─────▶ │  L3  RUN npm ci              │  shared,  │  L1  base: node:22-slim      │        │  L2  RUN apt-get install ... │  read-only  │                              │        │  L1  base: node:22-slim      │  └──────────────────────────────┘        └──────────────────────────────┘

👀 The drawing is revealed line by line. Arrows pulse, and ✅ / ❌ marks pop in to show the verdicts.

  • Layers are content-addressed (by sha256) and shared between images and containers. Ten containers from one image use the disk space of one image plus ten small writable layers.
  • Files changed inside a container use copy-on-write: the file is copied up into the writable layer first.

State machine · 5/6

🔁 Container Lifecycle

👀 States appear one after another and each transition draws in order. ● is the start and ◉ is the end.

Step by step

  1. ● → Created docker create
  2. Created → Running docker start
  3. ● → Running docker run
  4. Running → Paused docker pause
  5. Paused → Running docker unpause
  6. Running → Exited process ends / docker stop
  7. Exited → Running docker start
  8. Exited → ◉ docker rm
  9. Running → ◉ docker rm -f
